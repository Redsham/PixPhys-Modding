# Lua: типы данных, ноды и компоненты деталей

Mod API 2 позволяет создавать игровые предметы, собственные типы сигналов, самостоятельные ноды, ноды деталей и сохраняемые компоненты. Формат старых пакетов API 1 продолжает работать. Код выполняется через игровой API: файловая система компьютера, процессы, Steam и произвольные объекты .NET из Lua недоступны.

## С чего начать

Скопируйте одну папку из `Examples/Lua` в `GameData/Modifications/`, включите её через проверку версии и откройте конструктор. Примеры требуют версии игры с Mod API 2.

| Папка | Что добавляет | Как проверить |
| --- | --- | --- |
| `CustomDataBus` | Тип Telemetry, ноды упаковки, распаковки и подсчёта расстояния | Открыть редактор соединений, найти ноды по слову telemetry |
| `SignalThruster` | Двигатель с входами Throttle и Direction, выходами Force, Speed, Enabled | Разместить деталь, подключить число к Throttle, вектор к Direction |
| `StatefulComponents` | Два компонента одной детали: термостат и счётчик ударов | Изменить температуру через контекстное меню, столкнуть деталь, сохранить и загрузить конструкцию |

`CustomDataBus` не добавляет физический предмет: это пакет нод. В редакторе соедините выход Telemetry ноды Pack telemetry со входами Telemetry у Read telemetry и Telemetry distance counter. Входы Pack telemetry можно редактировать обычными средствами редактора. При запуске симуляции счётчик накапливает расстояние; после сохранения и загрузки он продолжает с прежнего значения. Вход Reset обнуляет его.

У SignalThruster по умолчанию Throttle равен нулю. Задайте значение от −1 до 1; направление задаётся в мировых координатах. Контекстное действие включает и выключает двигатель. Для сохранения добавляйте детали через каталог конструктора.

Минимальный `Modification.json`:

```json
{
  "Name": "My logic pack",
  "Author": "Your name",
  "ModificationVersion": "1.0.0",
  "Runtime": "lua",
  "ApiVersion": 2,
  "Scripts": ["main.lua"],
  "Active": true,
  "WorkshopID": 0
}
```

Спрайты и звук храните внутри папки мода. Для модулей используйте `require("lib.controller")`: он загрузит `lib/controller.lua` из пакета. Сначала регистрируйте типы данных, затем ноды и компоненты, после них — детали, которые на них ссылаются.

## Собственный тип данных

Тип сигнала — это именованная структура Lua. У неё есть независимые значения, цвет проводов, необязательная схема обязательных полей и постоянный идентификатор.

```lua
local Command = Mod.RegisterDataType {
    id = "Command",
    color = { r = 0.9, g = 0.5, b = 0.2 },
    fields = { power = "number", enabled = "boolean" },
    default = { power = 0, enabled = true, options = { mode = "auto" } }
}

local value = Types.New(Command, { power = 0.75 })
assert(Types.Is(value, Command))
```

`RegisterDataType` возвращает строковый идентификатор, который можно передать в `type` порта. `Types.New` копирует значение по умолчанию и заменяет переданные поля. Схема `fields` поддерживает `number`, `boolean`, `string`, `vector` и `table`. Все объявленные поля обязательны, поэтому значение `default` должно их содержать. Дополнительные поля, массивы и вложенные таблицы разрешены. Для произвольной структуры можно вообще не объявлять `fields`.

Вектор представлен таблицей `{x=число, y=число}`. Поле `__type` зарезервировано для идентификатора типа. При передаче по проводу значение проверяется и копируется: изменение полученной таблицы не изменяет сигнал отправителя.

В сигналах и состоянии разрешены конечные числа, строки, булевы значения, таблицы и ключи из строк, чисел или булевых значений. Функции, потоки, циклические ссылки, метатаблицы и объекты движка сохранять нельзя.

## Самостоятельная нода

```lua
Mod.RegisterNode {
    id = "Gain", name = "My gain", category = "Math",
    inputs = {
        { id = "Value", type = "number", default = 0 },
        { id = "Gain", type = "number", default = 2 }
    },
    outputs = { { id = "Result", type = "number" } },
    state = { changes = 0 },
    onInit = function(ctx)
        ctx.set("Result", ctx.inputs.Value * ctx.inputs.Gain)
    end,
    onInput = function(ctx, portId, value)
        ctx.state.changes = ctx.state.changes + 1
        ctx.set("Result", ctx.inputs.Value * ctx.inputs.Gain)
    end
}
```

Нода появляется в обычной палитре, поиске и списке совместимых нод при протягивании провода. Поддерживаются категории `Utils`, `String`, `Logic`, `Math`, `Vector`, `Comparison`, `Composite`, `Trigonometry`.

`inputs` и `outputs` — последовательные массивы описаний портов. Обязателен уникальный `id`; необязательны отображаемое `name`, `description` и `default`. В одном определении идентификаторы входов и выходов не повторяются. Встроенные типы портов: `boolean`, `number`, `string`, `vector`, `composite`. Композит передаётся таблицей каналов с индексами от 1 до 32. Пользовательский тип передавайте строкой, возвращённой `RegisterDataType`.

`ctx.set` вызывается через точку: `ctx.set("Result", value)`. Не используйте `ctx:set(...)`.

## Контекст и события

| Поле или функция | Назначение |
| --- | --- |
| `ctx.state` | Собственное сохраняемое состояние экземпляра |
| `ctx.inputs[id]` | Текущее значение входа |
| `ctx.set(id, value)` | Запись в выход с обычной передачей по проводам |
| `ctx.object` | Дескриптор детали; у самостоятельной ноды равен 0 |
| `ctx.restored` | Состояние восстановлено из сохранения |
| `ctx.editing` | Инициализация или событие происходят в режиме редактирования конструкции |

Можно менять поля `ctx.state` или заменить всю таблицу состояния. Остальные поля контекста считайте служебными. У каждого экземпляра ноды и каждого компонента своя таблица состояния.

| Обработчик | Когда вызывается |
| --- | --- |
| `onInit(ctx)` | После создания портов и восстановления состояния |
| `onInput(ctx, portId, value)` | Когда меняется вход во время симуляции |
| `onTick(ctx, dt)` | На фиксированном шаге симуляции; dt в секундах |
| `onUse(ctx)` | При выборе контекстного действия ноды детали или компонента |
| `onCollision(ctx, collision)` | При начале столкновения детали |
| `onDestroy(ctx)` | При удалении экземпляра во время симуляции |

`onInit` может выполняться в конструкторе: проверяйте `ctx.editing`, если действие должно влиять на мир только во время симуляции. `onTick` в режиме редактирования не запускается. Входы доступны в `onInit` сразу, отдельного начального события `onInput` нет. В `onInput` аргумент value относится к конкретному событию, а ctx.inputs содержит последние принятые значения. События ставятся в очередь; при исчерпании общего бюджета исполнение может продолжиться на следующем шаге.

Столкновение передаёт только числа: `speed`, `vx`, `vy` относительной скорости, а при наличии контакта — `x`, `y`, `nx`, `ny`. Ссылок на чужие объекты нет. `onUse` и `onCollision` предназначены для деталей. Не полагайтесь на `onDestroy` для сохранения: при завершении процесса он не гарантирован.

## Нода детали

```lua
local Motor = Mod.RegisterPropNode {
    id = "Motor", name = "Enable motor",
    inputs = { { id = "Force", type = "number", default = 0 } },
    outputs = { { id = "Enabled", type = "boolean" } },
    state = { enabled = true },
    onInit = function(ctx) ctx.set("Enabled", ctx.state.enabled) end,
    onUse = function(ctx)
        ctx.state.enabled = not ctx.state.enabled
        ctx.set("Enabled", ctx.state.enabled)
    end,
    onTick = function(ctx, dt)
        if ctx.state.enabled then World.ApplyForce(ctx.object, 0, ctx.inputs.Force) end
    end
}

Mod.RegisterProp {
    id = "MyMotor", base = "SmallMetalCube", name = "My Lua motor", node = Motor
}
```

Порты Lua добавляются к существующим портам базовой детали. На одну регистрацию детали можно назначить одну дополнительную ноду. Её входы и выходы отображаются на обычной ноде детали в редакторе. Сохранение сохраняет значения, идентификаторы портов и соединения.

Через `World.Ports(handle)` можно получить список портов с полями `id`, `name`, `direction`, `type`. `World.ReadPort(handle, id)` читает значение; `World.WritePort(handle, id, value)` меняет его через систему сигналов; `World.OnPort(handle, id, callback)` подписывается на дальнейшие изменения. Деталь должна быть связана с конструкцией. Для Lua-портов используйте постоянный id; для старых встроенных портов — их имя. Подписка не отправляет начальное значение автоматически.

## Компоненты без портов

```lua
local Heater = Mod.RegisterComponent {
    id = "Heater", name = "Increase temperature",
    state = { temperature = 30 },
    onUse = function(ctx) ctx.state.temperature = ctx.state.temperature + 10 end,
    onTick = function(ctx, dt) World.SetTemperature(ctx.object, ctx.state.temperature) end
}

Mod.RegisterProp {
    id = "HeatedBlock", base = "SmallMetalCube", name = "Heated block",
    components = { Heater }
}
```

На одной детали может быть до 32 разных компонентов и одна нода. Одно определение компонента можно использовать в нескольких типах деталей. Они имеют раздельное состояние, даже если выполняются в одном Lua-пакете. Компоненты начинают работать после привязки детали к конструкции. Для отдельных объектов, созданных через `World.Spawn`, по-прежнему можно использовать `onSpawn` и `Mod.OnTick`; само по себе это не добавляет объект в сохраняемую конструкцию.

## Работа с физикой и ресурсами

Игровые операции выполняются только над дескрипторами объектов этого мода. `World.Exists(handle)` проверяет, что объект ещё существует.

| Задача | API |
| --- | --- |
| Координаты, скорость, угол, масса, температура | `World.State(handle)` |
| Сила и импульс | `World.ApplyForce(handle,x,y)`, `World.ApplyImpulse(handle,x,y)` |
| Вращение | `World.ApplyTorque(handle,t)`, `World.SetAngularVelocity(handle,v)` |
| Положение и угол | `World.SetPosition(handle,x,y)`, `World.SetRotation(handle,degrees)` |
| Масса, гравитация, температура | `World.SetMass`, `World.SetGravityScale`, `World.SetTemperature` |
| Скорость | `World.SetVelocity(handle,x,y)` |
| Оформление | `World.SetColor(handle,r,g,b,a)`, `World.SetSprite(handle,path)` |
| Звук | `World.PlaySound(handle,path)` |
| Создание и удаление | `World.Spawn(localPropId,x,y)`, `World.Destroy(handle)` |

Силу применяйте в onTick без умножения на dt: интеграцию выполняет физический движок. Углы и угловые скорости задаются в градусах. Пути к картинкам и звукам ведут внутрь пакета.

## Сохранения и обновления модов

`ctx.state` сохраняется вместе с конструкцией. `Storage.Get/Set` — отдельное строковое хранилище всего мода, общее для его экземпляров и версий. Используйте его для общих настроек, а не для подмены состояния отдельных деталей.

Держите стабильными источник пакета, id типов, нод, компонентов и портов. Для локального пакета источником является путь папки, для мастерской — Workshop ID. Перенос локального пакета или публикация под новым ID меняет его пространство идентификаторов.

Порядок загрузки модов может меняться: пользовательские типы портов восстанавливаются по постоянному ID. Изменять отображаемые названия и описания можно. Существующие порты должны сохранять порядок, направление и тип данных. Несовместимая схема отклоняется с ошибкой, чтобы провод не получил другой смысл. При необходимости новой схемы зарегистрируйте новую ноду под новым id, оставив прежнюю для старых конструкций.

Для изменения состояния используйте собственную версию:

```lua
onInit = function(ctx)
    local version = ctx.state.version or 1
    if version < 2 then
        ctx.state.target = ctx.state.oldTarget or 30
        ctx.state.oldTarget = nil
        ctx.state.version = 2
    end
end
```

Не обнуляйте состояние в onInit без проверки: он вызывается и после загрузки. В сохранение попадают данные и идентификаторы определений; исполняемый код мода туда не копируется. Для загрузки требуется установленная совместимая версия мода.

## Пределы и диагностика

На пакет доступны 128 пользовательских типов данных и 256 определений нод/компонентов; в каждом направлении ноды — до 64 портов. Одно сохраняемое состояние или структурированный сигнал ограничены 64 КиБ, 4096 значениями и 16 уровнями таблиц. Прежние лимиты объектов, очереди и бюджета Lua сохраняются. Их назначение — останавливать ошибки и бесконечные циклы; они не ограничивают выбор алгоритма управления или структуру игровой логики.

Если мод остановился, откройте его статус в списке модификаций и журнал игры. Частые причины: неправильный тип сигнала, неизвестный id, изменённая схема портов, попытка записать функцию в состояние или обращение к удалённому объекту.
